# 설계 결정 기록

이 문서는 Developer Activity의 주요 설계 결정과 근거를 기록합니다. 구현 세부사항보다 선택의 배경, 결과, 재검토 조건에 집중합니다.

## D-001. 기능 중심의 단순한 구조를 유지한다

- 상태: 채택
- 날짜: 2026-08-11

### 맥락

현재 애플리케이션은 GitHub 사용자와 저장소를 조회하는 하나의 기능 영역으로 구성되어 있습니다. 아직 여러 외부 Provider를 교체하거나 복잡한 도메인 규칙을 격리해야 할 요구가 없습니다.

### 결정

`Controller → Service → GitHubClient` 흐름과 `developer` 기능 패키지를 유지합니다. Port, Adapter, UseCase 같은 별도 추상 계층은 도입하지 않습니다.

### 결과

- 요청 처리 흐름을 짧게 따라갈 수 있습니다.
- 추상화보다 외부 API 연동 정책 학습에 집중할 수 있습니다.
- Provider가 추가되어 실제 교체 경계가 생기거나 도메인 규칙이 복잡해지면 구조 분리를 재검토합니다.

## D-002. GitHub 연동에 Spring HTTP Interface를 사용한다

- 상태: 채택
- 날짜: 2026-08-11

### 맥락

GitHub API의 경로와 쿼리 파라미터를 명확한 계약으로 표현하면서 Spring Framework 7의 HTTP 클라이언트 기능을 학습할 필요가 있습니다.

### 결정

`RestClient`를 기반으로 한 Spring HTTP Interface에 GitHub API 계약을 선언합니다. GitHub 응답 DTO와 공개 API 응답 모델은 분리합니다.

### 결과

- GitHub 요청 형식이 `GitHubClient`에 모입니다.
- 외부 응답 변경이 공개 API에 직접 전파되지 않습니다.
- 클라이언트 인터페이스는 기술 선택에 필요한 것이므로 별도의 범용 인터페이스를 추가하지 않습니다.

## D-003. 자동 테스트는 실제 GitHub에 의존하지 않는다

- 상태: 채택
- 날짜: 2026-08-11

### 맥락

실제 GitHub API를 자동 테스트에서 호출하면 네트워크 상태, Rate Limit, 외부 데이터 변경으로 테스트가 불안정해집니다.

### 결정

- HTTP 계약은 `MockRestServiceServer`로 URI, 헤더, JSON 역직렬화를 검증합니다.
- 서비스 정책은 Mockito로 GitHub 클라이언트를 대체해 검증합니다.
- 공개 API는 MockMvc로 상태 코드, 입력 검증, 응답 형식을 검증합니다.
- timeout은 로컬 HTTP 서버의 지연 응답으로 실제 HTTP 클라이언트 설정까지 통합 검증합니다.
- 실제 GitHub 연결은 필요할 때 수동 smoke test로 확인합니다.

### 결과

자동 테스트를 외부 인터넷 없이 반복 실행할 수 있습니다. GitHub API 자체의 가용성은 자동 테스트 범위에 포함하지 않습니다.

## D-004. 외부 오류를 API 경계에서 명시적으로 변환한다

- 상태: 채택
- 날짜: 2026-08-11

### 맥락

GitHub 클라이언트의 예외를 그대로 노출하면 공개 API가 외부 구현 세부사항에 의존하게 됩니다.

### 결정

- 잘못된 요청 값은 `400 Bad Request`로 반환합니다.
- GitHub에 사용자가 없으면 `404 Not Found`로 반환합니다.
- GitHub의 기타 오류와 timeout이 아닌 연결 장애는 `502 Bad Gateway`로 반환합니다.
- GitHub의 연결 또는 응답 timeout은 `504 Gateway Timeout`으로 반환합니다.
- 오류 본문은 `ProblemDetail` 형식을 사용합니다.

### 결과

클라이언트는 외부 클라이언트 구현과 무관한 일관된 오류 형식을 받습니다. timeout 여부는 예외 메시지가 아니라 표준 timeout 예외 타입과 cause chain으로 판별합니다.

## D-005. 저장소 목록은 페이지 단위로 전달한다

- 상태: 채택
- 날짜: 2026-08-11

### 맥락

서버가 GitHub 저장소의 모든 페이지를 자동으로 순회하면 응답 시간, 메모리 사용량, Rate Limit 소비가 사용자별 저장소 수에 따라 크게 달라집니다.

### 결정

공개 API에서 `page`와 `size`를 받고 GitHub의 `page`와 `per_page`로 전달합니다. `page`는 1 이상, `size`는 1~100으로 제한하며 저장소는 최근 업데이트 순으로 요청합니다.

### 결과

호출 비용과 응답 크기가 예측 가능합니다. 여러 페이지를 합친 활동 요약이 필요해질 때 별도의 집계 정책과 Rate Limit 영향을 검토합니다.

## D-006. 모든 외부 HTTP 호출에 명시적인 timeout을 적용한다

- 상태: 채택
- 날짜: 2026-08-11

### 맥락

외부 API가 응답하지 않으면 애플리케이션 요청 처리 자원이 장시간 점유될 수 있습니다. 호출자가 일반적인 외부 장애와 시간 초과를 구분할 수 있어야 합니다.

### 결정

Spring Boot 4.1의 공통 HTTP 클라이언트 설정으로 연결 timeout 2초와 응답 timeout 5초를 적용합니다. 현재 auto-configured `RestClient.Builder`를 사용하는 모든 외부 호출에 같은 기본값이 적용됩니다.

시간 초과는 `504 Gateway Timeout`, 그 밖의 연결 장애는 `502 Bad Gateway`로 변환합니다. timeout은 예외 메시지가 아니라 `HttpTimeoutException`, `SocketTimeoutException`이 포함된 cause chain으로 판별합니다.

retry는 함께 도입하지 않습니다. 재시도는 호출 횟수, 지연 시간, GitHub Rate Limit을 증가시키므로 실제 실패와 지연을 관측한 뒤 별도 정책으로 결정합니다.

### 결과

- 외부 API가 느릴 때 요청이 무기한 대기하지 않습니다.
- 호출자는 시간 초과와 다른 외부 장애를 구분할 수 있습니다.
- 다른 외부 Provider에 서로 다른 timeout이 필요해지면 공통 설정 대신 HTTP Service 그룹별 설정을 재검토합니다.
- 멱등성, backoff, 재시도 대상 상태가 정의되기 전까지 retry를 추가하지 않습니다.

## 기록 원칙

다음 조건 중 하나에 해당할 때 이 문서를 갱신합니다.

- 여러 구현 대안 사이에서 장기적인 선택을 했을 때
- 외부 API, 데이터 또는 모듈 경계가 변경될 때
- 기존 결정을 폐기하거나 재검토했을 때

단순한 구현 세부사항과 임시 작업 목록은 기록하지 않습니다. 결정이 많아져 독립적인 이력 관리가 필요해지면 `docs/adr/` 아래의 개별 문서로 분리합니다.
